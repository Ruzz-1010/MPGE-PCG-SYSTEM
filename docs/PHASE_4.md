## Architecture
Migration 007 adds expiration_checks (37 domain tables), indexes, and fictional document types. Previous migrations 001–006 unchanged. Runtime SELECT/INSERT on new document and evidence tables; no UPDATE/DELETE on file metadata, historical document versions, reviews or evidence. Existing protectedRoute handles authorization and transactional audit writes. New document and photo writes use scoped record checks and revision/advisory locking. A raw octet-stream upload with URI-encoded JSON X-VW-Metadata header (max 6000 chars) avoids extra multipart dependency. Client sends X-VW-Browser for CSRF guard; existing authentication remains required. Two concurrent upload validation slots per API process, 20 MiB documents / 10 MiB photos, 16 megapixel image cap, filename extension and signature checks, Sharp full decode, qpdf structural check and encrypted PDF rejection; original bytes are retained. Structural validation is not malware scanning, sanitization or proof of authenticity. Upload timeouts and 10-photo cap are proposed demo defaults. PDF always delivered as attachment with nosniff and no-store. Image previews are decoded to canvas after authenticated retrieval; no public static URL.

Files are written under an opaque UUID in an absolute 0700 private directory outside the workspace, with 0600 file permissions, exclusive creation, file/directory sync, SHA-256 verification on every download. API database commits reference existing file bytes. If a transaction or process fails after storage, orphan blobs may remain; do not delete them blindly, reconcile against DB under an approved maintenance process. Database and filesystem are not a single atomic resource; actual backup/restore consistency must be demonstrated in Phase 8/backup work. Encryption at rest, AV scanning/quarantine, disk quota/monitoring, retention, orphan reconciliation and independently reviewed upload security are pending. No real PCG records.

## Run and operate locally
Use Phase 1.4 MFA setup. Rebuild Docker images (qpdf and Sharp added). The API has a separate named volume privatefiles mounted at /var/lib/vesselwatch/files; database has pgdata. Do not run down -v against a project whose data must be retained. For non-Docker development install qpdf, set VW_PRIVATE_DIR to an absolute private 0700 directory owned by the API user, outside web assets; do not place uploaded files in the repository. Open /workspace/. Use Documents for search, register, renew, verify and history; Inspections for draft photos. PDFs downloaded only, photos previewed locally after authorized retrieval. All three theme CSS palettes retained, original dist/ untouched.

## API
GET /api/document-types, /api/documents?format=page&q=&status=&vesselId=&page=1 (omit unused status/vesselId), /api/documents/expiry-summary, /api/documents/:id and /history?page=1.
POST /api/documents (binary + metadata filename,vesselId,typeId,required,number,issuer,issueDate,expiryDate,expiryKind); POST /api/documents/:id/renew (binary + metadata filename,version,number,issuer,issueDate,expiryDate,expiryKind). POST /api/documents/:id/review JSON version,status,reason,expectedReviewId. POST /api/inspections/:id/evidence binary + metadata filename,version. GET /api/files/:id scopes authorization through document or inspection revision links and checks checksum. No direct storage key is exposed.
